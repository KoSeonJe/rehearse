## 입력
RESUME_SKELETON:
{{SKELETON_JSON}}

SESSION_DURATION_MIN: {{DURATION_MIN}}
USER_LEVEL: {{USER_LEVEL}}

ALLOWED_CHAIN_IDS:
{{ALLOWED_CHAIN_IDS_JSON}}

위 ALLOWED_CHAIN_IDS 목록에 없는 chain_id는 절대 출력하지 말 것. 목록 외 chain_id를 사용하면 응답 전체가 무효화된다.

## 작업
위 Skeleton 으로부터 면접 Plan 을 생성한다. 다음 원칙을 엄격히 준수.

### 선정 원칙
1. 프로젝트 랭킹: 최근 + high priority claims 밀도 + 기술 스택 다양성. priority 1 부터 오름차순 부여. 모든 프로젝트 포함 (자르지 않음).
2. Chain 선정 per 프로젝트:
   - Skeleton chain 수 ≤ 5: 모두 포함. 상위 priority 2~3 을 primary, 나머지 backup.
   - Skeleton chain 수 > 5: priority 상위 5개만 사용 (primary 3 + backup 2). 6번째부터 제외.
   - Skeleton chain 수 = 1: primary 1 만 (backup 빈 배열).
3. 난이도 곡선 (USER_LEVEL × levels_to_cover):
   - JUNIOR: 첫 chain [1,2], 중반 [1,2,3], backup [1,2]
   - MID: 첫 chain [1,2,3], 중반 [1,2,3,4], backup [1,2,3]
   - SENIOR: 첫 chain [1,2,3,4], 중반 [1,2,3,4], backup [1,2,3,4]
4. duration_hint_min → opener 톤 (chain 선택/차단에는 사용 금지):
   - 15분: 1문장, 핵심 1개
   - 30분: 1~2문장, 핵심 1~2개
   - 45/60분: 2~3문장, 배경 + 결정 + 이유로 풍부하게

### Playground opener_question 톤 (강제)
- Playground = 응시자 맥락 파악 / 자유 회고 단계. opener_question 은 intro 톤만.
- 금지: "기술적 결정", "트레이드오프", "메커니즘", "어떻게 동작", "왜 그렇게 설계", "내부 원리" 류 narrow 기술 심문 어휘.
- 허용: "설명", "역할", "맡으셨", "흐름" 류 intro 어휘. "인상 깊은 / 어려웠던 경험" 류 감정·서사 anchor 금지 (응시자 무관 진부 패턴 회귀 방지).
- skeleton.projects[] 중 정확히 1개를 anchor (어느 거든 OK — 다양성 환영, 동일 skeleton 재호출 시 다른 프로젝트 선택 가능). 선택한 project_name 은 opener_question 에 반드시 명시. 누락 / "this project" / "해당 프로젝트" / "프로젝트들" 같은 지시·복수 표현 금지. 가공 명칭 / skeleton 외 프로젝트 명칭 생성 금지.

### 출력 스키마 (JSON, strict)
- session_plan_id (string, "plan_" prefix)
- duration_hint_min (number, 입력 그대로)
- total_projects (number)
- project_plans: [
    {
      project_id, project_name, priority,
      playground_phase: { opener_question, expected_claims_coverage: [claim text, ...] },
      interrogation_phase: {
        primary_chains: [{ chain_id, topic, priority, levels_to_cover: [1,2,3,4 부분집합] }],
        backup_chains: [{ chain_id, topic, priority, levels_to_cover }]
      }
    }
  ]

chain_id 는 ALLOWED_CHAIN_IDS 에 있는 값만 사용. 다른 값 생성 금지.
topic 은 Skeleton 에 존재하는 값을 그대로 사용 (수정·번역·생성 금지). topic 자체에 "::" 포함 금지.
project_name 은 RESUME_SKELETON 입력의 해당 프로젝트 project_name 값을 그대로 복사. 임의 생성·번역·줄임·영문 변환 금지.
expected_claims_coverage 의 각 element 는 Skeleton 의 해당 프로젝트 claims 배열에 존재하는 text 를 그대로 사용. 새 합성 / paraphrase / 요약 / 번역 금지.
total_projects 는 project_plans 배열 길이와 정확히 동일.
priority 는 1 부터 시작하는 연속 정수, 동순위 금지 (프로젝트 priority + chain priority 양쪽).
levels_to_cover 는 [1,2,3,4] 부분집합. 1=WHAT(무엇), 2=HOW(어떻게), 3=WHY_MECH(왜·메커니즘), 4=TRADEOFF(절충).

### 출력 금지 필드 (절대 포함하지 말 것)
- allocated_time_min
- max_turns
- estimated_duration_min

이유: 시간 기반 컷오프는 Orchestrator 가 런타임에 사용자 페이스로 결정. Planner 는 우선순위만 부여.

### Few-shot 예시

예시 — 1개 프로젝트, MID 레벨, duration=30분.
입력 RESUME_SKELETON 발췌 (project_name 명시):
```
projects: [
  { "project_id": "__example_proj__", "project_name": "__example_name__", "claims": [...], "implicit_cs_topics": [...] }
]
```
출력 (project_name 은 입력값 그대로 복사):
```json
{
  "session_plan_id": "plan___example___",
  "duration_hint_min": 30,
  "total_projects": 1,
  "project_plans": [
    {
      "project_id": "__example_proj__",
      "project_name": "__example_name__",
      "priority": 1,
      "playground_phase": {
        "opener_question": "__example_name__ 프로젝트에 대해 간단히 설명해주시고, 어떤 역할을 맡으셨는지 말씀해주세요.",
        "expected_claims_coverage": ["__example_proj_claim_text_1__"]
      },
      "interrogation_phase": {
        "primary_chains": [
          {
            "chain_id": "__example_proj__::__topic_a__",
            "topic": "__topic_a__",
            "priority": 1,
            "levels_to_cover": [1, 2, 3]
          }
        ],
        "backup_chains": [
          {
            "chain_id": "__example_proj__::__topic_b__",
            "topic": "__topic_b__",
            "priority": 2,
            "levels_to_cover": [1, 2]
          }
        ]
      }
    }
  ]
}
```

다수 프로젝트 시 매핑 규칙 (project_id ↔ project_name 1:1 보존):
입력 발췌:
```
projects: [
  { "project_id": "__proj_a__", "project_name": "__name_a__", ... },
  { "project_id": "__proj_b__", "project_name": "__name_b__", ... }
]
```
출력 project_plans 에서 각 항목의 project_name 은 동일 project_id 에 매핑된 입력값을 그대로 사용 (`__proj_a__` → `__name_a__`, `__proj_b__` → `__name_b__`). 항목 간 명칭 교차·치환 금지.

JSON 만 출력. 설명/마크다운 금지.
