## 본질 (One-liner)

**면접 유형 → 매핑된 루브릭 → 그 루브릭으로 피드백 생성**. 단일 패턴 = 차원별 (점수 + 한국어 코칭 문장 + 사용자 답변 발췌). 언어 영역 (verbal) / 비언어 영역 (음성·영상) 동일. 자유서술 / 결정론 보조 매퍼 / 원시 측정치 보조 경로 없음.

본 Epic 의 모든 결함 (영어 코칭 / 정의문 인용 / 산출 경로 이중화 / 자유서술 카드 4종 / 원시 측정치 노출 / 비대칭 차원 1개의 보조 매퍼 의존) = 위 패턴 미준수의 증상. 패턴 회복 시 동시 해결.

## 문제 상황 (Problem)

rubric 채점 결과가 DB 에 적재는 되고 있으나 (#472 결함 fix 직후 상태), 산출물의 품질이 사용자 코칭에 부적합하다. dev rehearse-db 직접 조회 (2026-05-16) + 화면 직접 확인 + 코드 추적으로 식별된 결함 5종.

- 현재 상태 (정상 동작 / 기존 흐름):
  - verbal 채점: LLM 호출 → 차원별 (점수 + 코칭 문장 + 답변 발췌) 산출 → 채점 결과 적재.
  - 비언어 분석: Lambda 가 자유서술 코멘트 (긍정 / 부정 / 제안) + 음성·태도·종합 자유서술 + 원시 측정치 (필러 횟수 / 톤 라벨 / 발화 속도 분산 / 카메라 응시 비율 / 자세 불안정 횟수 등) 산출. BE 가 결과 화면용 코멘트 4종을 자유서술 저장소에 적재.
  - 비언어 점수: 결정론 보조 매퍼가 원시 측정치 → 1-3 점수 매핑 → 4차원 (발화 유창성 / 자신감 있는 말투 / 시선과 자세 / 압박 안정성) 채점 결과 적재. 코칭 문장 / 답변 발췌는 비어 있음 (보조 매퍼라 산출 불가). 압박 안정성 차원은 난이도 medium 이상 turn 에만 적용 (turn 마다 차원 수 비대칭).
  - 결과 화면: 답변 / 점수 영역 + 비언어 전용 영역 이중 탭. 비언어 전용 영역에 자유서술 카드 + 원시 측정치 카드 노출.
- 발생 증상:
  - 증상 1 (verbal 코칭 언어): 이력서 루브릭 채점 코칭 30건 중 30건 (100%) ASCII 영문. 한국어 사용자 화면에 영어 코칭 노출.
  - 증상 2 (verbal 답변 발췌 정합): 답변 발췌가 사용자 답변 transcript 인용이 아닌 루브릭 정의문 또는 질문 본문 인용 사례 반복 ("팀에서 했어요 수준" = 루브릭 L1 정의문 / "리허설 프로젝트에 대해 좀 더 구체적으로..." = 질문 본문). 사용자 발화 그대로 활용 불가.
  - 증상 3 (비언어 산출 이중 경로): 동일 turn 에 자유서술 코멘트 + 결정론 매퍼 점수 동시 산출. 두 표현 공존 → 사용자·운영자 모두 어느 쪽이 신뢰 가능한 단일 출처인지 결정 불가.
  - 증상 4 (자유서술 4종 분기): 비언어 외에도 음성·태도·종합 영역 각각 자유서술 텍스트가 동일 turn 마다 적재. 차원 점수와 별개 경로 + 화면 별도 카드 = 동일 평가 영역에 표현 두 개.
  - 증상 5 (원시 측정치 노출): 결과 화면 비언어 전용 영역에 필러 횟수 / 카메라 응시 비율 / 자세 불안정 횟수 등 측정치 카드 표시. 사용자 입장에서 측정치 자체는 코칭이 아닌 raw 수치 → 차원 점수와 의미 중복 + 해석 부담.
- 사용자·운영 인지 채널:
  - dev rehearse-db (`54.180.188.135`) 직접 SQL 조회 (2026-05-16). 인터뷰 23~27 채점 결과 / 자유서술 영속 컬럼 전수.
  - LENGTH() vs CHAR_LENGTH() 비교로 multibyte 검출 → 이력서 루브릭 코칭 30/30 영어 확인.
  - 결과 화면 직접 확인 → 이중 탭 / 자유서술 카드 / 원시 측정치 카드 노출 식별.

## 왜 해야 하는가 (Why)

- 사용자 임팩트:
  - 영어 코칭 = 한국어 사용자에 즉시 신뢰 저하. 화면 노출 불가능 수준.
  - 정의문 / 질문 본문 인용 답변 발췌 = "내 답변 안 보고 코칭" 인식. 코칭 신뢰 0.
  - 자유서술 카드 4종 + 차원 점수 동시 표시 = 사용자가 동일 평가를 두 표현으로 마주침. "어느 쪽이 진짜 평가인가" 혼란.
  - 원시 측정치 카드 노출 = 코칭이 아닌 raw 수치 ("필러 8회 = 좋은가 나쁜가?" 사용자가 직접 해석 부담).
  - 이중 탭 = 동일 답변의 평가가 두 탭으로 흩어짐. 사용자가 종합 평가를 한 화면에서 받지 못함.
  - 압박 안정성 차원이 난이도 medium 이상 turn 에만 산출 = 동일 인터뷰 내 차원 수 비대칭. 사용자는 "왜 어떤 turn 만 4번째 차원이 있나" 일관성 없는 경험.
- 운영 / 시스템 임팩트:
  - 채점 결과 = 후속 통계·회차 비교·강약점 분석 입력. 영어 / 잘못된 답변 발췌 / 이중 경로 = 후속 분석 입력 오염 누적.
  - 보조 매퍼 + 자유서술 4종 컬럼 + 원시 측정치 영속 = 단일 source of truth 결정 불가. 회귀 검증 시 모든 경로 동시 점검 필요.
- 외부 압력:
  - 사용자 직접 발언 ("기존에 생성하던 비언어 코멘트를 제거하고, 루브릭 기준 바탕으로 피드백을 남겨주면 좋겠거든", "evidence quote도 이상해", "어 루브릭 배고 싹다 제거해", "유창성에서 떨림 끊김 같이 평가 안해? 표정 평가안하나? 압박 이런거 없어도 될것같은데 따로 분리하자머"). P1 (다음 sprint 까지).
  - #472 (적재 결함) fix 직후 새로 표면화. 신규 인터뷰 누적되며 데이터 자산 / 화면 품질 저하 계속 진행.

## 해결 방향 (Approach)

PM 수준 high-level. HOW (구현 디테일 = 어떤 클래스·파일·컬럼·도구) = `tech-spec.md`.

- 핵심 접근: **본질 one-liner 의 단일 패턴을 모든 면에 일관 적용**.
  - 적용 면 1 (verbal 코칭 출력): 코칭 문장 한국어 + 답변 발췌가 사용자 답변 transcript 의 발췌만 포함.
  - 적용 면 2 (비언어 산출 일원화): 자유서술 코멘트 4종 + 결정론 보조 매퍼 + 원시 측정치 노출 = 모두 폐기 (예외: 필러 카운트 배지는 결과 화면에서 유지 — 사용자 명시 결정). 대신 차원별 (점수 + 한국어 코칭 문장 + 사용자 답변 발췌) 단일 구조만 산출.
  - 적용 면 3 (비언어 차원 정의 정비): 4차원 → **3차원**. 압박 안정성 차원 폐기 (조건부 적용으로 비대칭 + 사용자 명시 "압박 이런거 없어도 될것같다" + 점수 의존성이 보조 매퍼 산물). 남은 3차원 (발화 유창성 / 자신감 있는 말투 / 시선과 자세) 의 정의 확장 — 음성 영역의 발화 유창성 차원이 "떨림·끊김" 을 흡수, 영상 영역의 시선·자세 차원이 "표정" 을 흡수 (사용자 명시 결정). 추가로 기존 원시 측정치 (말 속도 / 톤 라벨 / 속도 분산 / 시선 비율 / 자세 흔들림 / 표정 라벨) 는 **산출 자체가 부재** — LLM 호출이 직접 차원별 (점수 + 한국어 코칭 문장 + 사용자 답변 발췌) 만 산출 (사용자 명시 — "raw 완전삭제. 점수는 dimension 기반으로 점수 생성"). 차원 정의의 측정 기준 (rubric measurement / observable) 이 LLM 의 채점 가이드 역할. 단 필러 카운트만 예외 — 별도 raw 신호로 유지 (FE 배지용, 사용자 명시).
  - 적용 면 4 (Lambda 책임 분리): 음성 분석기 / 영상 분석기가 각자 자기 영역 차원 평가를 산출. BE 가 두 결과를 조립 (사용자 명시 결정 흔적).
  - 적용 면 5 (BE 적재 정합): 비언어 채점 결과의 코칭 문장 / 답변 발췌가 NOT NULL 로 동반 저장. 산출 결과 검증 실패 시 자동 회복 경로가 동작 (구체 정책 = tech-spec).
  - 적용 면 6 (결과 화면 표시): 결과 화면이 단일 흐름 (탭 분리 부재). 차원 카드가 verbal·비언어 동일 형태 (점수 + 코칭 + 답변 발췌). 자유서술 카드 / 원시 측정치 카드 / 비언어 전용 영역 모두 화면 트리에서 부재.
  - 적용 면 7 (저장소 정리): 결과 화면용 자유서술 4종 저장소 + 압박 안정성 차원 정의 / 채점 / 적재 경로 = 자산 / 코드 / 정의 자산 / 적재 결과 모두에서 부재.
- 대안 비교 (1줄):
  - "verbal 결함만 본 Epic, 비언어는 별도" — 미채택. 본질 one-liner 분리 시 절반만 회복. 사용자도 "싹다 제거" 명시.
  - "보조 매퍼 유지 + LLM 코칭 문장만 추가" — 미채택. 보조 경로 잔존 → 중복 산출 미해결.
  - "압박 안정성 4차원 유지 + 비대칭 분기 보존" — 미채택. 사용자 가치 낮음 명시 + 보조 매퍼 의존.
  - "비언어 전용 탭 유지 + 자유서술 카드만 제거" — 미채택. 답변·평가 한 화면 통합 원칙 위반.
  - "원시 측정치 사용자 토글 옵션 유지" — 미채택. 코칭 산출물에서 raw 수치 자체가 비스코프.

## 결과 화면 변화 계획 (사용자 관찰 결과 한정)

PM 수준. 정확한 컴포넌트 / 상태 / 흐름 = `tech-spec.md`.

- 결과 화면 흐름: 단일 흐름 (탭 분리 부재). 사용자는 답변 / 점수 / 코칭을 한 흐름에서 확인.
- 차원 표시 단위: 한 차원 = 한 묶음. 묶음 내용 = (이름·점수 / 한국어 코칭 문장 / 사용자 답변 발췌). 자유서술 카드 / 원시 측정치 카드 (필러 카운트 인디케이터 배지 제외) / 압박 안정성 묶음 부재.
- 영역 그룹: 언어 영역 그룹 + 비언어 영역 그룹 (비언어 = 3차원). 그룹 헤더 표현 (평균 점수 / 차원 수 등) = tech-spec.
- Empty 상태 (사용자가 마주칠 수 있는 케이스):
  - 분석 진행 중 — "분석 중" 안내 노출. 자유서술 카드 부재로 화면 빈 영역 발생해도 무한 대기 차단 (대기 종료 메커니즘 = tech-spec).
  - 음성 / 영상 분석 한 쪽 실패 — 받은 영역만 차원 표시 + 다른 영역 = "이번 답변 비언어 분석 일부 실패" 안내 1줄. 사용자는 받은 코칭으로 다음 진행 가능.
- 변화 인지 지점: 기존 비언어 전용 탭 진입 / 외부 공유 링크 자체 부재 (기능 화면에서 제거). 외부 링크 부재 운영 안내는 본 Epic 비스코프.

## Goal

검증 = **회귀 테스트 코드**로 단일화. 측정 채널 = 각 Goal 단위 명시. 정확한 테스트 레이어 (단위 / 통합 / E2E / 마이그레이션 smoke / FE 컴포넌트) 결정 = tech-spec 위임.

- [ ] Goal-1 (verbal 코칭 언어): verbal 채점 코칭 문장이 한국어를 포함. ASCII-only 출력 0건이 회귀 테스트로 보호 (채점 산출물 단위).
- [ ] Goal-2 (verbal 답변 발췌 정합): verbal 채점 답변 발췌가 사용자 답변 transcript 의 발췌. 루브릭 정의문 또는 질문 본문 인용 사례 0건이 회귀 테스트로 보호 (채점 산출물 단위).
- [ ] Goal-3 (비언어 단일 패턴): 비언어 채점 결과가 차원별 (점수 + 한국어 코칭 문장 + 사용자 답변 발췌) 단일 구조. 자유서술 코멘트 / 결정론 보조 매퍼 / 원시 측정치 산출이 응답·코드·DB 어디에도 부재. 회귀 테스트로 보호 (분석 응답 + 적재 산출물 단위).
- [ ] Goal-4 (비언어 3차원 일원화): 비언어 채점이 발화 유창성 / 자신감 있는 말투 / 시선과 자세 3차원만 산출. 압박 안정성 차원 row 0건. 정의 자산 / 적재 결과 모두에서 압박 안정성 부재. 회귀 테스트로 보호 (채점 결과 단위). 정의 자산 내 "떨림·끊김" / "표정" 포함 여부는 운영자 리뷰 검증.
- [ ] Goal-5 (BE 적재 정합): 비언어 채점 결과의 코칭 문장 / 답변 발췌가 NOT NULL 로 동반 저장 (적재 대상 turn 한정). 적재 누락률 0%. 회귀 테스트로 보호 (적재 산출물 단위).
- [ ] Goal-6 (결과 화면 단일 흐름): 결과 화면이 단일 흐름. 이중 탭 / 자유서술 카드 / 원시 측정치 카드 / 압박 안정성 묶음이 화면 트리에서 부재. 차원 카드가 verbal·비언어 동일 패턴 (점수 + 코칭 + 발췌). 회귀 테스트로 보호 (화면 트리 단위).
- [ ] Goal-7 (저장소 정리): 결과 화면용 자유서술 4종 저장소가 schema 에서 부재. 코드·테스트·응답에서 해당 저장소 참조 0건. 회귀 테스트로 보호 (schema 상태 + 코드 참조 단위).
- [ ] Goal-8 (부분 실패 대기 차단): 음성 / 영상 분석 중 한 쪽 실패 시 받은 영역만 차원 적재 + 화면 안내 1줄 + 결과 화면 무한 대기 0건. 회귀 테스트로 보호 (분석 부분 실패 시 화면 상태 단위).

## Non-Goals (추구하지 않는 가치)

- 항목 B — 점수 결과 시각화 고도화 (차트 / 회차 비교 / 강약점 시각화). 차원 카드 단일 패턴 일관화까지 한정.
- 항목 C — 본 Epic 은 nonverbal 차원 정비까지. verbal / technical / resume 차원 정의 변경은 추구하지 않음.

## 수용 기준 (Acceptance Criteria)

검증 단일 채널 = **자동화 회귀 테스트 코드**. 테스트 레이어 = tech-spec 위임.

- [ ] AC-1 (verbal 코칭 언어): verbal 채점 코칭 문장이 한국어 포함. ASCII-only 출력 0건이 회귀 테스트로 보호.
- [ ] AC-2 (verbal 답변 발췌 정합): verbal 채점 답변 발췌가 동일 turn 사용자 답변 transcript 의 substring. 루브릭 정의문 또는 질문 본문과의 substring match 0건이 회귀 테스트로 보호.
- [ ] AC-3 (비언어 응답 단일 패턴): 비언어 분석 응답이 차원별 (점수 + 한국어 코칭 문장 + 사용자 답변 발췌) 단일 구조만 산출. 자유서술 텍스트 / 원시 측정치가 응답에 부재. 회귀 테스트로 보호. (구체 응답 키 / 필드 = tech-spec.)
- [ ] AC-4 (비언어 3차원 일원화): 비언어 채점 결과에 압박 안정성 차원 row 0건. 발화 유창성 / 자신감 있는 말투 / 시선과 자세 3차원만 적재. 회귀 테스트로 보호.
- [ ] AC-5 (비언어 적재 코칭·발췌 누락 0%): 비언어 채점 적재 시 코칭 문장 / 답변 발췌가 누락 0% (적재 대상 turn 한정). 검증 실패 시 자동 회복 경로가 동작 (구체 정책 = tech-spec). 회귀 테스트로 보호.
- [ ] AC-6 (결과 화면 단일 흐름 + 단일 카드 패턴): 결과 화면이 단일 흐름 (탭 분리 부재). 자유서술 카드 / 원시 측정치 카드 / 압박 안정성 묶음이 화면 트리에서 부재 (예외: 필러 카운트 인디케이터 배지 1건 유지). 차원 카드가 verbal·비언어 동일 패턴 (점수 + 코칭 + 발췌). FE 컴포넌트 회귀 테스트로 보호.
- [ ] AC-7 (자유서술 4종 저장소 부재): 결과 화면에 노출되던 자유서술 4종이 화면 / 응답 / 영속 저장소 모두에서 부재. 마이그레이션 검증 + 회귀 테스트로 보호. (구체 도구 / 컬럼명 = tech-spec.)
- [ ] AC-8 (부분 실패 회복): 음성 / 영상 분석 중 한 쪽 실패 시 받은 영역만 차원 적재 + 화면 안내 1줄 + 결과 화면 무한 대기 차단 (대기 종료 메커니즘 = tech-spec). 회귀 테스트로 보호.
