## 1회성 작업 (배포 전 / 후)

### Backfill SQL — questionType sentinel → sub-type 전환

**대상**: `question` 테이블의 `question_type='MAIN'` / `'FOLLOWUP'` row.
**환경**: dev → prod 순차 실행.
**전제**: PR #437 (`feat/427-question-sub-type-enum`) 머지된 코드가 해당 환경에 배포된 직후.
**중요**: prod 데이터 = MAIN / FOLLOWUP 적재 row 다수 존재 (#427 PR1 = column 적재만 중단, 기존 row 보존). backfill 미실행 시 Phase 1.6 (sentinel 제거) 진입 불가.

#### 백필 SQL (수동, 1회성)

```sql
-- backfill-V46-pre.sql (수동 실행, 환경별 사전 백업 후)

-- 1) STANDARD 트랙 row 매핑
UPDATE question q
JOIN question_set qs ON q.question_set_id = qs.id
SET q.question_type = CASE
    WHEN qs.category = 'BEHAVIORAL'    AND q.question_type = 'MAIN'     THEN 'BEHAVIORAL_MAIN'
    WHEN qs.category = 'BEHAVIORAL'    AND q.question_type = 'FOLLOWUP' THEN 'BEHAVIORAL_FOLLOWUP'
    WHEN qs.category <> 'RESUME_BASED' AND q.question_type = 'MAIN'     THEN 'TECH_MAIN'
    WHEN qs.category <> 'RESUME_BASED' AND q.question_type = 'FOLLOWUP' THEN 'TECH_FOLLOWUP'
    ELSE q.question_type
END
WHERE q.question_type IN ('MAIN', 'FOLLOWUP');

-- 2) 검증: 잔여 MAIN/FOLLOWUP 0
SELECT COUNT(*) AS remain FROM question WHERE question_type IN ('MAIN', 'FOLLOWUP');
-- 기대: 0

-- 3) 검증: RESUME_BASED + MAIN/FOLLOWUP 잔여 0 (V44 가정)
SELECT q.id, q.question_type, qs.category
  FROM question q JOIN question_set qs ON q.question_set_id = qs.id
 WHERE qs.category = 'RESUME_BASED' AND q.question_type IN ('MAIN','FOLLOWUP');
-- 기대: 0 row. 1+ row 시 Phase 1.6 진행 보류 후 분석.
```

#### 검증 SQL (잔여 0 row 확인)

-- 검증 #2: STANDARD 트랙 잔여 0 확인

-- 검증 #3: RESUME_BASED 카테고리 잔여 0 확인

  FROM question q JOIN question_set qs ON q.question_set_id = qs.id
 WHERE qs.category = 'RESUME_BASED' AND q.question_type IN ('MAIN','FOLLOWUP');

### 절차

1. **사전 백업** — RDS 스냅샷 또는 mysqldump
2. **dev 적재** — backfill SQL 실행 → 검증 SQL → 잔여 0 확인
3. **회귀 관찰** — 1-2일 dev 운영. 신규 인터뷰 / 기존 인터뷰 follow-up 분기 / rubric 매핑 정상 확인
4. **prod 적재** — dev 검증 통과 후 동일 절차
5. **Phase 1.6 진입 조건** — dev + prod 모두 잔여 0 row + 회귀 0건

## 영향 범위 / 위험

- **영향 row**: 기존 STANDARD 트랙 (TECH / BEHAVIORAL) 모든 question
- **운영 영향**: read path 가 enum fallback 으로 이미 환원 → backfill 전후 동작 동등 (잘못 적재된 컬럼 정정 외)
- **롤백**: backfill 은 `MAIN` / `FOLLOWUP` 다시 UPDATE 로 복원 가능 (원 컬럼 = sub-type 매핑 역추적). 사전 백업 보존 권장
- **DB 스키마 변경 X**: Flyway DDL 없음. DML 만
