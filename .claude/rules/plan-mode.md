# Plan Mode Rule

Claude Code Plan Mode (ExitPlanMode) 활용 시 작성하는 플랜 문서 규칙. 영구 문서 (`docs/plans/{YYYY-MM-DD-topic}/tech_spec/design.md`) 는 사용자가 명시 요청 시에만 별도 작성. 폴더 구조는 루트 `AGENTS.md` "Spec-Driven Work" 섹션 참조.

## 작성 원칙

- 모호한 부분 발견 시 **즉시 사용자에게 되묻는다**. 자율 판단으로 채우지 않는다.
  - 요구사항 범위, 제약, 수용 기준, 우선순위, 비기능 요구 등.
  - 한 번에 한 질문씩. 다중 선택지 형태 권장.
- 모든 모호함 해소 후 플랜 제출.

## 필수 섹션

### 1. Why
어떤 문제를 왜 해결하는가. 배경 + 동기.

### 2. Goal
측정 가능한 결과. "사용자 X가 Y를 할 수 있다", "응답 시간 Nms 미만" 등 검증 가능 형태.

### 3. Evidence
근거 데이터 / 리서치 / 기존 코드 분석 / 사용자 발화. 추측 명시.

### 4. Trade-offs
선택지 비교. 포기한 대안. 채택 사유.

### 5. Tasks
단계별 작업 항목. 각 task 마다 다음 명시:

```
## Task N: <title>
- Implement: `<agent_name>` — <역할>
- Review: `<agent_name>` — <검증 포커스>
- 병렬 가능 시 [parallel] 태그
```

**에이전트 배정 룰**:
- 적합 에이전트 존재 시 해당 에이전트 명시.
- 적합 에이전트 부재 시 사용자에게 추천:
  > "이 task 는 기존 에이전트로 커버 안 됨. <역할> 전담 에이전트 신규 생성 어떨까요? (`/agent-creator` 활용)"
- 사용자 결정 후 진행.

### 6. Verification
구현 완료 판정 기준.
- 테스트 통과 목록 (단위/통합/E2E)
- 빌드/린트 통과
- 관찰 가능한 동작 검증 방법
- 회귀 체크 항목

### 7. Pre/Post Implementation State
- **Pre**: 현재 상태 (어떤 파일/동작이 어떻게 존재).
- **Post**: 구현 후 기대 상태 (변경된 파일/동작/스키마).
- diff 형태 비교 가능하게.

## 승인 게이트 (Blocking)

- 플랜 제출 → 사용자 **명시 승인** 전 코드 변경 금지.
- "혼자 판단해서 진행" 금지.
- CI 통과 / 단순함 / 테스트 작성됨 — 모두 우회 사유 안 됨.
- 승인 범위는 제출한 플랜 그대로. 도중 범위 확장 시 플랜 갱신 + 재승인.

## 구현 후 (Post-Impl)

- 플랜 Verification 항목 모두 통과 확인 후 보고.
- 지정 리뷰어 병렬 실행 필수 (스킵 금지).
- 미완 task 발생 시 사용자에게 상태 보고 + 후속 결정 요청.

## 안티 패턴

- Why 없이 What 만 나열.
- Goal 이 "잘 동작한다" 같은 비측정 표현.
- Task 에 에이전트 미배정.
- Verification 이 "테스트 작성" 만 (통과 기준 없음).
- 모호함을 "일단 해보고" 로 우회.
