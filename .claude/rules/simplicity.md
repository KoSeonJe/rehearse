# Simplicity & Surgical Changes Rule

Karpathy 가이드라인 기반. 모든 코드 변경 (구현 / 리팩 / 리뷰) 적용.

## Simplicity First

요청한 것만 구현. 추측 추상화 금지.

- 요청 외 기능 추가 X.
- 단발성 코드에 추상화 / 인터페이스 / 옵션 만들지 말 것.
- 발생 불가 시나리오에 방어 코드 / 에러 핸들링 추가 X (boundary 만 검증).
- 확장성 / 재사용성 명시 요구 없으면 1회용 코드로 작성.
- 200줄 가능한 걸 50줄로 가능하면 50줄로.

**Self-check**: "시니어가 보면 과한 설계라 할까?" Yes → 단순화.

## Surgical Changes

요청한 라인만 손댄다. 인접 코드 자율 정리 금지.

- 인접 코드 / 주석 / 포맷 "개선" 금지.
- 망가지지 않은 것 리팩 금지.
- 본인 스타일 다르더라도 기존 스타일 유지.
- 무관한 dead code 발견 → **삭제 X, 발견 사항으로 보고** (`reporting.md` 형식).
- 본인 변경 결과 생긴 orphan (unused import / 변수 / 함수) 만 같이 제거. 기존 dead code 제거 = 사용자 명시 요청 시만.

**Self-check**: 변경된 라인 1줄마다 사용자 요청과 직접 연결되나? No → 되돌림.

## 예외

- 사용자 명시 요청 ("리팩해줘", "정리해줘", "단순화") 시 본 룰 완화. 단 범위 = 사용자 명시 영역만.
- 보안 위반 (`security.md` OWASP Top 10) 발견 = 본 룰 우선순위 ↓. 즉시 보고 + 진행 결정 받음.

## 안티 패턴

- 버그 1개 고치며 주변 함수 같이 리팩.
- 단일 호출 메서드에 strategy 패턴 도입.
- "혹시 모를 미래" 위해 옵션 / config 추가.
- 요청 외 dead code 정리하며 PR 비대화.
- 기존 컨벤션 어긋나는 본인 스타일 적용.
